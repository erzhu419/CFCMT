# 济南右转让行的源场景筛选

现有18个源网络均缺少稳定相位中的右转让行绿灯 `g`。盐湖的有冲突让行转向为左转，遇到优先直行时驶向不同出口。Grid4x4有64对专用右转与优先直行汇入同一车道，但使用须先停车的 `s`。Bologna有局部同车道的 `g/G`，可用程序缺少保持右转、切换直行优先权的动作对，原网络也未通过历史安全准入。[源库盘点](source_static.json) · [历史动态记录](existing_evidence.json) · [库外核查](external_static.json) · [SUMO信号定义](https://sumo.dlr.de/docs/Simulation/Traffic_Lights.html#signal_state_definitions)

济南20个状态中，18个有近停止线车辆可右转（10/10种子），12个同时有近端优先直行车辆（7/10种子）。这12个状态有15个符合条件的右转，双方均用专用进口，汇入同一出口道路。已按动作前信息为每个右转固定一对动作，两臂的右转信号整整10秒相同，直行在右转让行期间的优先放行时间分别为4秒和0秒。[目标观测](target_context.json) · [15对动作](phase_pair_roster.json)

杭州与济南的原始CityFlow首阶段都只开放右转，这些右转贯穿随后8个稳定相位。按进出道路逐相位比较，两城发布输入与实际SUMO路网的放行转向集合分别有128/128、96/96相符。现成杭州包的64个右转一律为优先绿灯 `G`，济南v9的48个一律为 `g`。进一步要求同出口车道、直行可切换且路口规则明确规定右转让行时，分别有32/64、24/48个右转符合。杭州2983辆车的路线和计划出发时刻均能对上。两城路网使用了不同的信号编码约定，值得单独检验。[程序核对](cityflow_programs.json)

杭州旧数据的8个状态中，只有2个同时观察到有向同车道冲突双方的近端车辆，原名义信号为 `G/G`。这限定了可期待的动态覆盖。CityFlow文件列出允许的转向，优先权由转换约定和SUMO路口规则共同决定。[杭州动作前供给](hangzhou_supply.json)
